## Context

Willyboxd's shipped brand mark (the `brand-identity` change) is a "slate box": a tall rounded box with two diagonal stripes in `currentColor`. The user rejected it. This session we drafted and implemented a v3 iteration — three black stacked circles on an amber rounded tile — which the user also rejected as not phallic enough, and supplied the approved reference: three rockets (rounded capsules with fins, nozzle and white window) in orange/green/blue, outer two tilted outward. The user confirmed: keep exactly that orange/green/blue palette ("make sure this is a design theme going forward") and render transparent on dark surfaces, with a background only where contrast demands it (favicon/static tiles). This design is now canonical.

The app ships 4 dark runtime themes (amber default, spotify, runway, linear); header and auth pages sit on the dark `--color-bg`. Static assets live in `apps/client/public/`; PNGs are generated by Pillow (`make-icons.py`) because `qlmanage` proved unreliable (brand-identity design.md D4). `BrandMark` is an inline SVG sized via `className`.

## Goals / Non-Goals

**Goals:**
- Faithfully reproduce the approved three-rocket trio as the brand mark.
- A mark that reads phallic (rocket = nose + shaft + fins) while staying a plausible abstract "three things" logo at 16px favicon size.
- Full-surface application: header, auth pages, favicon, launcher icons, OG/social meta — all from one geometry.
- Fixed orange/green/blue palette, theme-agnostic, contrast-safe on all 4 dark themes; transparent in-app.
- Bigger in the title bar: `w-10` (40px).
- Zero new runtime/CI dependencies; PNGs regenerable from SVG masters via the existing Pillow pipeline.

**Non-Goals:**
- No reintroduction of the amber tile or the three-circle stack.
- No redesign of app UI, no new pages, no server/shared changes.
- No change to the runtime theme system.
- No CI-based icon generation (regeneration is a local dev task).

## Decisions

### D1. Mark geometry: the approved three-rocket trio (240×120 viewBox)

Reproduce the user-supplied reference exactly. Each rocket (drawn at origin, centred on y=60 via translate):

- **Capsule body** — a vertical rounded capsule: `rounded_rectangle([-17, -42, 17, 40], radius=17)`. (The reference path is exactly this capsule: straight sides from y=−20 to y=18, semicircular caps of radius 17.)
- **Fins** — two side triangles near the base: left `M-17 6 L-30 22 L-17 18 Z`, right mirrored.
- **Nozzle** — `rect(-5, 38, 10, 9, rx=3)` at the base.
- **Window** — white circle `cx=0 cy=-8 r=5` at the nose, opacity 0.9.

Three instances on the 240×120 viewBox:

| instance | colour        | transform                  |
|----------|---------------|----------------------------|
| left     | `#F57C00`     | `translate(78 60) rotate(-18)` |
| centre   | `#44C553`     | `translate(120 60)`            |
| right    | `#29B6F6`     | `translate(162 60) rotate(18)`  |

Rocket content spans roughly x 48..192 and y 18..109 in the viewBox (aspect ≈ 1.6:1).

**Alternatives considered:** the three-circle vertical stack (implemented and rejected this session — reads as a snowman, insufficiently phallic). A horizontal Letterboxd-style disc row — does not read phallic. Single rocket — not "three circles"-like and too on-the-nose. The approved reference wins; it is faithful to the user's supplied design.

### D2. Brand mark palette: fixed orange/green/blue, canonical going forward

- Orange `#F57C00`, green `#44C553`, blue `#29B6F6` — exactly as supplied by the user.
- This is the **canonical brand mark design and palette**; all future surfaces use it.
- Theme-agnostic: the mark does NOT inherit `text-accent` and does not change per runtime theme. All 4 dark themes provide enough contrast for these bright colours.
- The white window stays part of each rocket (detail; effectively invisible at 16px, fine).

**Alternatives considered:** black silhouette rockets (user's earlier preference, superseded by the coloured reference). Brand-colour trio (amber + two) — user chose the exact reference palette.

### D3. Surface: transparent on dark in-app; dark ink tile for static

- **In-app** (`BrandMark` in header/auth): transparent — the coloured rockets sit directly on the dark `--color-bg`, Letterboxd-style.
- **Static** (`favicon.svg`, `mark-tile.svg`, `apple-touch-icon.svg`, `og.svg` + PNGs): the rockets sit on a dark ink `#0F172A` background — a rounded-square tile for favicon/launcher, the full ink canvas for OG — so they stay visible where there is no app background. Brand ink matches `theme-color` and the OG canvas.

**Alternatives considered:** keep the amber tile behind the rockets everywhere (rejected — user chose transparent-on-dark and the amber tile was part of the rejected draft). Light tile (rejected — inconsistent with brand ink).

### D4. `BrandMark.tsx` as an inline SVG component

Keep the component shape: `<svg aria-hidden="true" focusable="false">` sized via `className`. Use a `<defs>` rocket + three `<use>` instances with the D1 transforms and fills (or three equivalent `<g>`s). No `clipPath`, no `useId`, no `--color-bg` knockout. Transparent background.

### D5. Static asset set + generation script

- `favicon.svg` (64: ink rounded-square tile + rockets scaled/cropped to fit).
- `mark-tile.svg` / `apple-touch-icon.svg` (512: ink tile + rockets scaled ×≈2.1).
- `og.svg` (1200×630: ink canvas + larger rockets + amber wordmark).
- `make-icons.py`: draw each rocket in PIL — capsule `rounded_rectangle`, fin polygons, nozzle `rounded_rectangle`, white window — render per-instance, rotate ±18° (resample=BICUBIC), composite onto the tile/canvas. Regenerate PNGs via `generate-icons.sh`; verify dimensions with `sips` and pixels with PIL.
- **Do not reintroduce `qlmanage`** (brand-identity design.md D4).

### D6. Application sizes

- Header: `<BrandMark className="w-10 h-10" />` — 40px wide, ~20px tall at the 2:1 aspect; confirm it reads well in the `h-14` header during QA.
- Login/Register: keep `w-14` (56px); no `text-accent`.

## Risks / Trade-offs

- [PIL rotation/paste must match the SVG transforms] → Compute offsets from the same translate/rotate parameters; pixel-check samples at known points; user eyeballs PNGs.
- [Rocket detail (fins/nozzle/window) lost at 16px favicon] → Acceptable; the trio reads as a coloured abstract mark, which is the plausible-deniability goal.
- [Mark no longer honours `text-accent` / theme accent] → Intended; fixed palette is the canonical design.
- [No visual QA possible in-session (model cannot view images)] → Geometry is a faithful reproduction of the user's reference; user eyeballs generated PNGs before merge.
- [OG `og:image` must be absolute URL for real scrapers] → Pre-existing, unchanged; documented deploy step.

## Migration Plan

Redraw only: new `BrandMark.tsx` + SVG masters under `public/`, edits to `BrandMark.test.tsx`, `Header.tsx`, `Login.tsx`, `Register.tsx`, `make-icons.py`, plus regenerated PNGs. No schema/API/data migration. Rollback is a single commit revert. Verification: `npm run lint && npm run typecheck && npm run test && npm run build`, then manual eyeball of header mark (all 4 themes), auth pages, favicon, and OG image.
