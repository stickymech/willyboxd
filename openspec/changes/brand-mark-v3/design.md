## Context

Willyboxd's shipped brand mark (the `brand-identity` change) is a "slate box": a tall rounded box with two diagonal stripes in `currentColor`. The user rejected it. This session we iterated v3: three black stacked circles on an amber tile (rejected as not phallic enough), then a three-rocket row (approved, then superseded — did not read as Letterboxd), then the current approved mark: a **Letterboxd-style disc-trio** — three overlapping discs in orange/green/blue, each containing an upright rocket silhouette. The user confirmed: keep exactly that orange/green/blue palette ("make sure this is a design theme going forward") and render transparent on dark surfaces, with a background only where contrast demands it (favicon/static tiles). This design is now canonical.

The app ships 4 dark runtime themes (amber default, spotify, runway, linear); header and auth pages sit on the dark `--color-bg`. Static assets live in `apps/client/public/`; PNGs are generated by Pillow (`make-icons.py`) because `qlmanage` proved unreliable (brand-identity design.md D4). `BrandMark` is an inline SVG sized via `className`.

## Goals / Non-Goals

**Goals:**
- Reproduce the approved Letterboxd-style disc-trio as the brand mark.
- A mark that reads phallic (sausage ship = domed glans + shaft + balls + rocket fins) while staying a plausible abstract "three things" logo at 16px favicon size.
- Full-surface application: header, auth pages, favicon, launcher icons, OG/social meta — all from one geometry.
- Fixed orange/green/blue palette, theme-agnostic, contrast-safe on all 4 dark themes; transparent in-app.
- Prominent in the title bar: `w-28 h-14` (112×56) mark with a `text-4xl md:text-5xl` wordmark in a wrap-friendly `py-3` header (settled after overall-polish QA found `w-20 h-10`/`text-2xl` too small).
- Zero new runtime/CI dependencies; PNGs regenerable from SVG masters via the existing Pillow pipeline.

**Non-Goals:**
- No reintroduction of the amber tile or the three-circle stack.
- No redesign of app UI, no new pages, no server/shared changes.
- No change to the runtime theme system.
- No CI-based icon generation (regeneration is a local dev task).

## Decisions

### D1. Mark geometry: Letterboxd-style trio of discs containing rockets (240×120 viewBox)

The mark evokes the Letterboxd logo: three overlapping coloured discs arranged diagonally, each containing an upright rocket silhouette (the phallic read).

- **Discs** — `r=42`, drawn bottom-to-top so each overlaps the next (blue then green then orange):
  - orange `#F57C00` at (64, 44) — topmost
  - green `#44C553` at (120, 60)
  - blue `#29B6F6` at (176, 76) — bottommost
- **Rockets** — inside each disc, brand ink `#0F172A`, drawn at `translate(cx cy) scale(0.8)` as a **sausage-shaped phallic ship**:
  - domed glans `path("M-13 -18 C-13 -40 13 -40 13 -18 L-13 -18 Z")` (wider than the shaft so it reads as a mushroom shoulder),
  - sausage body `path("M-10 -18 L10 -18 L12 24 C12 30 -12 30 -12 24 Z")`,
  - two balls `circle(±9,35,r=8)` (enlarged per user QA — draw the fins first so they tuck behind the balls),
  - two small rocket fins `path("M±11 22 L±19 32 L±13 29 Z")`,
  - and a white window `circle(0,-8,r=3.5)` opacity .9.
  No splayed tail fins — the previous fin/rect silhouette read as a fish tail.
- Content spans x 22..218, y 2..118 (aspect ≈ 1.7:1). At 16px favicon the trio reads as three coloured discs (Letterboxd-like); at header size the rockets inside read phallic but remain deniable.

**Alternatives considered:** the three-rocket row (approved first, then superseded — did not read as Letterboxd). The rejected three-circle snowman stack. A single rocket-with-balls logo (the balls were instead folded into each disc's rocket). The user settled on "three rockets or three circles containing rockets so that it looks like the letterboxd website logo"; the disc-arrangement wins.

### D2. Brand mark palette: fixed orange/green/blue discs + ink rockets, canonical going forward

- Discs: orange `#F57C00`, green `#44C553`, blue `#29B6F6` — exactly as supplied by the user.
- Rockets: brand ink `#0F172A` silhouettes with a white window — visible on the coloured discs and against the ink static tiles.
- This is the **canonical brand mark design and palette**; all future surfaces use it.
- Theme-agnostic: the mark does NOT inherit `text-accent` and does not change per runtime theme. All 4 dark themes provide enough contrast for these bright colours.

**Alternatives considered:** black silhouette rockets alone (superseded). Brand-colour trio (amber + two) — the user chose the exact reference palette.

### D3. Surface: transparent on dark in-app; dark ink tile for static

- **In-app** (`BrandMark` in header/auth): transparent — the coloured discs sit directly on the dark `--color-bg`, Letterboxd-style.
- **Static** (`favicon.svg`, `mark-tile.svg`, `apple-touch-icon.svg`, `og.svg` + PNGs): the discs sit on a dark ink `#0F172A` background — a rounded-square tile for favicon/launcher, the full ink canvas for OG — so they stay visible where there is no app background. Brand ink matches `theme-color` and the OG canvas.

**Alternatives considered:** keep the amber tile behind the rockets everywhere (rejected — user chose transparent-on-dark and the amber tile was part of the rejected draft). Light tile (rejected — inconsistent with brand ink).

### D4. `BrandMark.tsx` as an inline SVG component

Keep the component shape: `<svg aria-hidden="true" focusable="false">` sized via `className`. Three overlapping `<circle>` discs (blue, green, orange — bottom to top) then three `<g>` rocket silhouettes positioned at each disc centre via `translate(cx cy) scale(0.8)`. No `clipPath`, no `useId`, no `--color-bg` knockout. Transparent background.

### D5. Static asset set + generation script

- `favicon.svg` (64: ink rounded-square tile + disc trio scaled/cropped to fit).
- `mark-tile.svg` / `apple-touch-icon.svg` (512: ink tile + disc trio scaled ×≈2.1).
- `og.svg` (1200×630: ink canvas + larger disc trio + amber wordmark).
- `make-icons.py`: draw each disc `ellipse` and each rocket in PIL — domed glans, sausage body, two balls, two rocket fins, white window — composite onto the tile/canvas. Regenerate PNGs via `generate-icons.sh`; verify dimensions with `sips` and pixels with PIL.
- **Do not reintroduce `qlmanage`** (brand-identity design.md D4).

### D6. Application sizes

- Header: `<BrandMark className="w-28 h-14" />` (112×56) with a `text-4xl md:text-5xl` wordmark in a `py-3` header that wraps the nav on narrow screens. Iterated during QA: `w-7` → `w-10` (too small) → `w-32 h-16`/`text-6xl`/`h-24` (too big) → `w-28 h-14`/`text-5xl`/`h-20` → `w-20 h-10`/`text-2xl` (too small) → `w-28 h-14`/`text-4xl md:text-5xl` (current).
- Login/Register: keep `w-14` (56px); no `text-accent`.

## Risks / Trade-offs

- [PIL composition must match the SVG disc/rocket geometry] → Compute offsets from the same translate/scale parameters; pixel-check samples at known points; user eyeballs PNGs.
- [Rocket detail (nozzle/window) lost at 16px favicon] → Acceptable; the trio reads as three coloured discs (Letterboxd-like), which is the plausible-deniability goal.
- [Mark no longer honours `text-accent` / theme accent] → Intended; fixed palette is the canonical design.
- [No visual QA possible in-session (model cannot view images)] → Geometry follows the Letterboxd-style arrangement the user requested; user eyeballs in-browser + generated PNGs before merge.
- [OG `og:image` must be absolute URL for real scrapers] → Pre-existing, unchanged; documented deploy step.
